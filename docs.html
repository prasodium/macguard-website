MacGuard documentation

MacGuard is a native macOS app. While armed, it watches your charger. If the charger is unplugged, it sounds an alarm, asks macOS to lock the screen, looks up the Mac's location and emails you. It is a deterrent and recovery aid, not a guarantee.

Overview

When the charger is pulledWhat MacGuard does
1. AlarmStarts at once, repeats until you stop it or reconnect the charger.
2. Screen lockRequests a session lock and reports whether it could confirm it.
3. LocationAsks Core Location for a fix, with a time limit. Works only if you allowed it.
4. EmailSends an alert to your verified address through Brevo. Queued if you are offline.
5. LogRecords every step in the Event History.

The alarm and lock never wait for the email or the location. If email fails, the alarm still sounds.

Requirements

  • macOS 13 or newer. Built for Apple Silicon (arm64).
  • To build: the Xcode Command Line Tools (xcode-select --install). Full Xcode is not required.
  • For email (optional): a free Brevo account and a Gmail or other address you can read.

Install

There is no signed download yet, so you build the app yourself. It takes a few minutes.

git clone https://github.com/prasodium/MacGuard.git
cd MacGuard
scripts/build_app.sh release
cp -R dist/MacGuard.app /Applications/
open /Applications/MacGuard.app

The app is signed ad hoc. On first launch macOS may block it: right-click the app, choose Open, then confirm. Look for the lock icon in the menu bar.

On first run a short setup guide offers to test the alarm, the screen lock and location. Every step is optional, and nothing locks your screen unless you press the button.

Set up email

Open Settings → Email (the gear icon on the dashboard).

  1. Create a Brevo account and verify one sender address in it. No domain is needed.
  2. Create an API key in Brevo (the Get a key… button opens the page).
  3. Brevo section: paste the key, enter the verified sender, press Save. MacGuard checks the key with Brevo and stores it in your Keychain. Touch ID or your password is asked first.
  4. Gmail section: enter your address, press Send code, type the 6-digit code you receive, press Verify.
  5. Turn on Send email alerts and press Send test email.

Until an address is verified, alerts are held, never sent anywhere. Codes expire after 15 minutes, lock after 5 wrong tries, and you can request 3 per hour. If you change the address later, the old one gets a notice.

An email that Brevo accepts is not proof it reached your inbox. Check spam if it is missing.

Using MacGuard

Arm

Plug in the charger, then press Arm Protection. MacGuard shows what it sees and asks you to confirm. It will not arm if the power state is unknown or the charger is not connected.

When it triggers

The dashboard shows ALARM ACTIVE with the incident, lock result, location result and email status. Reconnecting the charger stops the alarm by default (changeable in Settings → Alarm). Protection stays armed, and unplugging again starts a new incident.

Stop and disarm

Stop Alarm and Disarm Protection ask for Touch ID or your Mac password. The prompt is the system's own. MacGuard never sees your password.

Closing the window

The window can be closed; MacGuard keeps protecting from the menu bar. Quitting while armed needs authentication.

After a restart

If Resume protection after a restart is on, MacGuard re-arms itself on launch, but only if the charger is connected. It never invents an incident because it was not running.

Find My recovery

  1. Turn on Find My Mac and the Find My network in System Settings → your name → iCloud.
  2. Check you can sign in to the same Apple Account on another device.
  3. Open icloud.com/find and select the Mac.
  4. Use Mark as Lost to lock it with a passcode if needed.
  5. If you think it was stolen, contact the police. Do not confront anyone.

MacGuard cannot read Find My locations, never asks for your Apple password and never automates Apple sign-in. Whether Find My shows a current location depends on Apple's service and the Mac's state.

Limitations

Read this. MacGuard cannot prevent shutdown, force-quit, or removal of all power, and it has no effect while the Mac is off or asleep.
  • Charger monitoring works only while MacGuard is running. If the app is killed or the Mac shuts down, nothing is detected. A gap is logged on the next start but never turned into a fake incident. A Mac unplugged while asleep counts as a real unplug when it wakes.
  • Alarm can be inaudible if the speakers are muted or audio goes to headphones. It cannot play during sleep.
  • Screen lock protects a running session only. macOS has no public "lock now" call, so MacGuard uses a private system function and falls back to sleeping the display. It says "verified" only when macOS confirms the lock.
  • Location is an estimate and needs permission and a network. It can be old. It is never guessed from an IP address. It is not live tracking.
  • Email needs internet. If the Mac never reconnects, nothing is sent.
  • Arming on battery is intentionally not supported.

Security

  • The Brevo key is on your Mac, in the Keychain, readable by the app while the Mac is locked so alerts can still go out. It is never written to files or logs. Trade-off: someone with access to your logged-in account could use it to send mail through your Brevo account. Keep the screen lock on, use a key only for MacGuard, and delete the key in Brevo if the Mac is lost.
  • Verified address only. Alerts go nowhere until an address proves itself with the emailed code.
  • Owner authentication uses the system prompt for Disarm, Stop Alarm, quitting while armed, and changing email settings.
  • HTTPS only to Brevo. Local data is stored with owner-only permissions.
  • One private API: the screen-lock call, used only on an incident or an explicit test.
  • No root, no background daemon, no tricks to stop you quitting or uninstalling.

Found a vulnerability? Please open a private security advisory on the GitHub repository.

Privacy and data

There is no MacGuard server, account, analytics or telemetry.

  • On your Mac: event log, incidents, queued alerts and saved locations in ~/Library/Application Support/MacGuard (owner-only), settings, and the Brevo key in the Keychain. Defaults: events kept 90 days, locations 7 days, both adjustable.
  • Sent out: only alert and verification emails, through your own Brevo account to your verified address. An alert contains the incident id, device name and model, macOS version, battery, power states, times, alarm and lock status, and the location if available.

Troubleshooting

"Cannot arm"

The charger is unplugged or the power state cannot be read. Plug in, then check Monitoring on the dashboard.

The alarm did not sound on a second unplug

Fixed in current versions: an unplug after a reconnect is a new incident. Rebuild from the latest source. If it still happens, check the Event History and open an issue.

Location unavailable

Allow MacGuard in Location Services and run Test Location in Settings → Tests. Run the signed .app; a bare binary cannot get the prompt.

Test email fails

The message says why. "Rejected the key": save a fresh key. "Sender is not verified": verify that sender address in Brevo. "No verified alert address": finish the Gmail step. Also check spam.

Screen lock shows "not verified"

The lock call may be unavailable on your macOS version and the fallback only slept the display. Set Lock Screen to require the password immediately.

Login item does not start

Approve MacGuard in System Settings → General → Login Items.

Settings look out of date

Update to the latest source; older builds refreshed some values only after switching tabs.

Uninstall

Disarm first, then from the repository:

scripts/uninstall.sh

This removes the app, ~/Library/Application Support/MacGuard, preferences and the Keychain item. Then delete the API key in Brevo and remove MacGuard from Login Items and Location Services if listed.

For developers

scripts/test.sh                  # Swift tests
scripts/build_app.sh debug       # build dist/MacGuard.app
dist/MacGuard.app/Contents/MacOS/MacGuard --self-check --play     # hardware smoke test

The project is a Swift package: MacGuardCore (all logic, no UI) and MacGuard (SwiftUI app). With only the Command Line Tools, @State and Swift Testing macros have no compiler plugin by default, so the UI uses a small @Local wrapper and scripts/test.sh loads the testing plugin explicitly. Architecture notes are in ARCHITECTURE.md.

Release: SIGN_IDENTITY="Developer ID Application: …" scripts/package.sh, then notarize with xcrun notarytool and staple. Not yet done for this project.
